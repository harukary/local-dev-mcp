# フィードバックと継続的な改善

`local-dev-mcp` は、`tool.usage` の利用統計だけでは分からない不具合や改善案を記録するMCPツールを提供します。報告は利用者自身が動かすMCPサーバーに保存され、GitHub Issueへの投稿や開発元への送信、ホスト間の同期は自動で行われません。

## 報告対象

再現する不具合、不足している機能、誤解を招くツール説明、繰り返し発生する非効率を報告します。通常のリトライで解消する一時的な通信エラーは報告しません。

認証情報、実ユーザーのデータ、会話全文、認証済みページのHTML、ツールの引数・応答全文は含めないでください。保存前のマスキングは補助的な対策であり、すべての機密情報を検出するものではありません。

## 登録

以下は`feedback.report`に渡す**説明用のMCP引数例**です。実在する不具合を主張するものではありません。

```json
{
  "kind": "bug",
  "title": "大きな一括読み込みが途中で切れる",
  "description": "複数ファイルをまとめて読むと内容が途中で終わる。どの結果が省略されたか分かる説明がほしい。",
  "impact": "同じファイルを読み直す必要がある。",
  "related_tool": "workspace.batch",
  "suggestion": "省略した結果と理由を明示する。"
}
```

`kind` は `bug`・`improvement`・`missing_feature` のいずれかです。`title` と `description` が必須で、`impact`・`related_tool`・`suggestion`・`project_id` は任意です。

プロジェクト未選択でも登録できます。ChatGPTでは選択中のプロジェクトを補完し、Claudeは必要なら`context_id`から作業コンテキストのプロジェクトを補完できます。Museは必要に応じて`project_id`を指定します。関連プロジェクトがない場合はサーバー全体の課題として扱います。

同じプロジェクト・種類・関連ツール・正規化したタイトルの報告は自動的に集約されます。結果の`id`、`occurrences`、`created`を確認できます。既知の再発を報告するときは`existing_id`を指定します。解決済みの場合は再オープンされ、`reopened`が増加します。

## 一覧・対応状況

以下はシェルコマンドではなく、**MCPツールに渡すJSON引数**です。

未解決課題を取得するには、`feedback.list`を呼び出します。

```json
{"status":"active","limit":50}
```

既定の`active`は`open`と`in_progress`を含み、プロジェクトを指定しなければ全プロジェクトが対象です。最近変更された報告を解決済みも含めて取得する場合:

```json
{"status":"all","recent_days":7,"limit":100}
```

`project_id`や`kind`で絞り込めます。`has_more`がtrueなら、返された`next_offset`を次の`offset`に指定して続きを取得します。結果には`total`が含まれ、一度に取得できるのは最大100件です。

調査中の状態を記録するには`feedback.update`を呼び出します。

```json
{"id":"fb_12345678-1234-4123-8123-123456789abc","status":"in_progress","note":"現行サーバーで再現を確認した。"}
```

修正と検証が終わったら`status: "resolved"`と、空ではない`resolution`を指定してクローズします。対応不要と判断した場合は`status: "dismissed"`にし、理由を`resolution`へ残します。`latest_note`は最新の経過のみを保持し、完全な変更履歴ではありません。

## 週次レビュー

次の作業は手動でも実施できます。また、自分のMCP Appを接続したChatGPTのScheduled Taskにも設定できます。リポジトリを導入しただけではタスクは作成されません。

> 毎週、`tool.usage`の`recent_days=7`で呼び出し回数、失敗・部分失敗、所要時間を確認する。`feedback.list`を`status=active,limit=100`で実行して未解決課題をすべて取得し、`next_offset`があれば続きも取得する。さらに`status=all,recent_days=7,limit=100`で新規・再発・最近解決した報告を確認する。定量情報と定性情報を照合し、未検証の報告と実証済みの問題を区別する。影響、発生頻度、再発回数、実装工数を基に改善候補を1〜3件提案する。新規報告がなければその旨を記す。このレビューではコードや報告の状態を変更しない。

Scheduled Taskの利用には、対応するChatGPT環境、接続済みApp、対象ツールへのアクセスが必要です。

## 保存・セキュリティ・制限

- 保存先は実行ホストの`~/.local-dev-mcp/runtime/feedback.json`です。Gitには保存されず、最初の報告時に作成されます。ディレクトリは0700、ファイルは0600の権限で扱います。
- 同じMCPサーバーへ接続するChatGPT・Claude・Museは報告を共有します。別ホストの`local-dev-mini`は別の保存領域を持ち、Git同期では報告データを同期しません。
- クライアント種別、関連プロジェクト、日時、状態、発生・再オープン回数を記録します。ツールの引数、応答全文、会話本文は自動収集しません。
- 書き込みは直列化し、一時ファイルからの置き換えで保存します。データが破損した場合は黙って初期化せずエラーにします。上限は5,000件です。
- 報告データは運用上の機微情報として扱ってください。機密文字列のマスキングは限定的なので、送信前に内容を確認してください。

プロジェクト全体に対する改善提案やプルリクエストは[貢献ガイド](../CONTRIBUTING_ja.md)を参照してください。脆弱性に関する報告は公開Issueや`feedback.report`ではなく、[SECURITY.md](../SECURITY.md)の非公開手段を利用してください。
